# AIS Data Pipeline and Viewer

AIS is a side-channel in RegattaView. It is logged from NMEA 2000 raw BoatBrain
files, extracted into per-MMSI JSON, and then sliced into small generated web
payloads for `review.html` and `tracks.html`.

## Architecture

Keep AIS separate from the main 10 Hz parquet pipeline.

Do **not** add AIS PGNs to `Libraries/bb_log.py::PGN_WHITELIST`. The parquet
pipeline flattens records into one instrument row per time step; AIS has many
boats, each with its own position stream, so flattening would overwrite boats
within the same time window.

```text
Raw BBLog files
  └─ Scripts/extract_ais.py
       └─ /Users/viola/Data/SailingData/AISLogs/YYYY-MM-DD_ais.json
            ├─ Analyze/slice_ais_starts.py → Analyze/AIS/<event_id>.json
            └─ Analyze/slice_ais_day.py    → Analyze/AISDays/<date>.json + index.json
```

## Firmware Capture

AIS logging started after the BoatBrain firmware update on 2026-04-13. Before
that, AIS PGNs were present on the bus but discarded because they had no handler
entry in `Arduino/include/nmea.hpp`.

Logged AIS PGNs:

- `129039` — AIS Class B Position Report
- `129809` — AIS Class B static data, Part A
- `129810` — AIS Class B static data, Part B

The firmware handlers are intentionally stubs; the raw NMEA frames are written
to the SD log and parsed later on the laptop.

## Raw AIS Extraction

Run manually:

```bash
conda run --no-capture-output -n sailing python Scripts/extract_ais.py --date 2026-05-09
```

Output:

```text
/Users/viola/Data/SailingData/AISLogs/2026-05-09_ais.json
```

`extract_ais.py` groups data by MMSI and suppresses our own transponder MMSI
(`338204092`) from competitor AIS output. Our boat appears in web payloads from
the processed ego GPS/parquet track instead.

Important timestamp detail: raw BBLog filenames are UTC dates. A Seattle
sailing day can cross UTC midnight, so day-level web payloads merge all UTC AIS
extracts touched by the local ego-log time span.

## Web Payloads

### Per-Start Review AIS

`Analyze/slice_ais_starts.py` consumes the per-UTC-date AIS extracts plus
`Analyze/events_index.json` and writes:

```text
Analyze/AIS/<event_id>.json
```

These files are lazy-loaded by `review.html` when inspecting an event. They are
small, event-window slices filtered to nearby boats.

### Per-Day Tracks AIS

`Analyze/slice_ais_day.py` consumes the same AIS extracts plus the local
sailing-day parquet logs and writes:

```text
Analyze/AISDays/index.json
Analyze/AISDays/YYYY-MM-DD.json
```

Only days with usable AIS overlap and at least one nearby boat are included in
`index.json`. Generated `Analyze/AISDays/` files are ignored by git and are
regenerated by the pipeline.

Default behavior:

- Local day = date prefix of processed ego logs in
  `/Users/viola/Data/SailingData/PandasLogs/`.
- Nearby boats = closest approach to our interpolated ego track under the
  configurable threshold, currently `600 m`.
- Full in-window AIS tracks are kept in the payload; the UI controls how much
  track history is rendered.
- J/105 aliases are loaded from `Analyze/ais_fleets.yaml` and added as tags,
  not used as a hard filter. This keeps non-J/105 nearby boats available for
  discovery.

Manual generation:

```bash
conda run --no-capture-output -n sailing python Analyze/slice_ais_day.py --days 30
conda run --no-capture-output -n sailing python Analyze/slice_ais_day.py --date 2026-05-09
```

## Viewer

`tracks.html` is the day-level AIS viewer:

```text
http://localhost:9000/tracks.html
http://localhost:9000/tracks.html?date=2026-05-09
```

The page loads `Analyze/AISDays/index.json` for the landing page and
`Analyze/AISDays/<date>.json` for a selected day. It provides:

- Search by boat name, AIS name, MMSI, callsign, and sail number.
- Filters for J/105 tags, named vessels, and selected vessels.
- Sorting by J/105-first, closest approach, name, or AIS sample count.
- Per-boat `Show` and `Track` toggles.
- A time scrubber with markers at the current time and a trailing two-hour
  track history.

The base map is OpenStreetMap. Local NOAA Seattle chart/depth tiles are exposed
as an optional overlay at `/SeattleTiles/...` in dev and `www/SeattleTiles/...`
in prod.

## Pipeline Integration

`Scripts/race_upload.py` runs AIS processing as part of the Analyze stage:

1. Refresh recent `/Users/viola/Data/SailingData/AISLogs/YYYY-MM-DD_ais.json`
   extracts when their source BBLog signature changes.
2. Run `Analyze/slice_ais_starts.py --days <N>` for `review.html`.
3. Run `Analyze/slice_ais_day.py --days <N>` for `tracks.html`.
4. Stage `Analyze/AIS/` and `Analyze/AISDays/` under `/Users/viola/www/Analyze/`.

`aws_sync.sh` then syncs the staged Analyze tree to:

```text
s3://regattaanalysis/www/Analyze/AIS/
s3://regattaanalysis/www/Analyze/AISDays/
```

Production browsers fetch those paths through the same Lambda-signed data URL
mechanism used by `review.html`.
